## 1. Arquitetura do Motor Combinatório
- **Opção Escolhida**: Opção 1 — NexusScale Engine (Motor Combinatório Cartesiano 1-to-N com síntese neural local e renderização em lote).
- **Justificativa**: Permite multiplicar 1 tema em dezenas de variações de alta tração com diferentes headlines, ganchos visuais e chamadas para ação para teste A/B de retenção no TikTok, Shorts e Reels, com custo marginal R$ 0,00 e renderização ultrarrápida.

## 2. Escopo & Mecânica
- **Combinação Cartesiana**: $N = H \text{ (Hooks)} \times B \text{ (B-rolls)} \times C \text{ (CTAs)}$.
- **Configuração Declarativa**: Arquivo de matriz JSON ou parâmetros diretos via CLI `--scale`.
- **Exportação Estruturada**: Cada variação é salva em subdiretório ou nomenclatura única (`output/scale_<batch_id>_<idx>.mp4`) com sumário JSON de metadados das variações.

## 3. Critérios de Aceite Inegociáveis (EARS)
1. **[REQ-SCALE-01]**: O sistema DEVE processar matrizes combinatórias contendo listas de ganchos, B-rolls e CTAs, gerando o produto cartesiano de testes A/B.
2. **[REQ-SCALE-02]**: O sistema DEVE permitir limitar a quantidade máxima de variações geradas (`--count` / `max_variations`) de forma determinística ou aleatória com seed reproduzível.
3. **[REQ-SCALE-03]**: O sistema DEVE sintetizar o áudio neural, alinhar legendas karaoke via Whisper e montar o vídeo final para cada variação gerada.
4. **[REQ-SCALE-04]**: Se a matriz de entrada contiver listas vazias ou caminhos inexistentes, o sistema DEVE levantar exceções tipadas defensivas (`ScaleMatrixError`) com mensagens diagnósticas claras.
